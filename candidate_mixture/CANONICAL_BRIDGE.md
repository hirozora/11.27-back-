# 固定动作头，只换执行者概率

[主仓库的三种子完整开发结果](https://github.com/hirozora/11.27/blob/cb165beb738e7b5bd53394211f2c2d447000d0b8/onball_participation/results/event13/RESULTS.md)已经检验区域内个人历史：给两组同样的预测球员和区域权重，个人动作倾向相较位置组倾向使十三类 NLL 在主、延迟视图下降 **0.0063、0.0058**；折叠十类下降 **0.0053、0.0049**。大部分收益来自粗类区分，而不是普通传球的方向。在给定真执行者的诊断中，个人相较位置组的十三类优势增至 0.0192、0.0203；只给真区域则为 0.0070、0.0067。真值不用于正式推断。[短预算的另一条实验](CPU_PILOT.md)没有同样的区域与历史倾向分支，不能反驳完整结果。

## 哪种执行者改进能传到动作预测？

复算种子 20260715 的两个主仓库头，锁定各候选各区域的动作分布，保持每位候选人的条件区域分布不变。只替换球员概率：从归档联合分布计算 `P_old(zone|player)`，再用 `q_new(player) * P_old(zone|player)` 加权。全局区域边缘概率可随之变化。备用模型比较同一预算的 12 轮、每场每轮 32 条动作，只有归属位的使用有别；共享表示重新拟合，动作评分时仅取其 q。逐条核对比赛与事件、候选 ID 集、真执行者、折叠标签、备选模型的执行者 NLL，并在 57 场的 64,975 / 64,966 条可达开发动作上复现归档原始概率（最大误差小于 5e-7，无样本剔除）。

| 归属位关闭 → 开启：NLL 降幅 | 主视图 [95% 区间] | 全部延迟两秒 [95% 区间] |
|---|---:|---:|
| 执行者 | +0.16543 [0.15888, 0.17189] | +0.03911 [0.03624, 0.04198] |
| 十三类：固定位置组动作头 | +0.00129 [0.00064, 0.00191] | +0.00070 [0.00039, 0.00101] |
| 十三类：固定个人动作头 | +0.00223 [0.00153, 0.00293] | +0.00082 [0.00048, 0.00116] |
| 十三类：个人头收益减位置组头收益 | +0.00094 [0.00065, 0.00124] | +0.00012 [-0.000004, 0.00024] |
| 折叠十类：固定个人动作头 | +0.00180 [0.00112, 0.00246] | +0.00083 [0.00050, 0.00117] |

区间为按比赛配对重抽 10,000 次，单种子，不覆盖训练变异。短预算中更好的执行者概率可以小幅改善**同一个已拟合动作头**。个人倾向额外受益的证据只在主视图明显。归属位开启的短训 q **没有击败**主仓库完整训练的 q；个人头十三类 NLL 分别差 +0.01689、+0.01159。因此不是模型替换建议。两路上下游都曾在同一开发期选择权重，未使用时间留出测试。

下一步只做一次匹配预算的验证：主仓库执行者—区域模型中新增候选归属位，对照用同尺寸的输入但全部置零。先做种子 20260715、严格延迟视图；两组采用主仓库相同的 120 轮和每场 128 条轮转，再做固定动作头的换权，重点看十三类个人头 NLL 是否超过原完整训练，以及个人头相对位置组头是否额外受益。未见效果再考虑改变动作倾向估计，不先换编码器。

## 复算

归档与视图分片来自主仓库上述固定提交。由仓库根目录合并 `onball_participation/results/view_parts/*.npz.part-*`（按视图、文件名顺序拼接），分别得到 `main.npz` 和 `lag.npz`。备用的 `real-views` 按本仓库 README 生成（含归属窗口）；每个视图重跑 `off-mixture` 和 `on-mixture`，训练参数为 `--device cpu --epochs 12 --per-match 32 --seed 20260715`，其余保持默认。环境需 Python 3.10+、NumPy、pandas、PyArrow、PyTorch。以下示例从备用仓库根目录运行，数据与输出路径按本地位置替换：

```bash
c=../11.27/onball_participation
view=lag
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python candidate_mixture/canonical_bridge.py \
  --canonical "$c" --data "$c/results/$view.npz" \
  --matches "$c/results/event13/inputs/matches.parquet" \
  --archive "$c/results/event13/${view}_20260715" \
  --backup-data "real-views/$view.npz" \
  --off "cpu-pilot/$view/off-mixture/20260715" \
  --on "cpu-pilot/$view/on-mixture/20260715" --out "${view}_bridge.json"
```

[主视图完整统计](bridge_main.json) · [延迟视图完整统计](bridge_lag.json)。只发布汇总，不发布本地生成的逐事件预测。

## 归属位让模型更会找角色，还是更会找同角色中的球员？

将执行者概率拆成位置组概率总量 `Q(g)` 与组内权重 `C(i|g)`，交叉组合关闭和开启归属位的两个来源。未知角色按球员单列，空槽不给概率；两个视图所有可达开发样本都包含至少一个多人已知角色组。对任一因素，分别在另一因素关闭和开启时计算替换收益，再取这两个收益的平均。两项之和逐条等于关闭→开启的实际 NLL 改善。

| NLL 降幅分解 | 主视图：组间 | 主视图：组内 | 延迟：组间 | 延迟：组内 |
|---|---:|---:|---:|---:|
| 执行者 | +0.09330 | +0.07213 | +0.02368 | +0.01544 |
| 十三类：固定位置组动作头 | +0.001165 | +0.000125 | +0.000669 | +0.000034 |
| 十三类：固定个人动作头 | +0.001694 | +0.000538 | +0.000757 | +0.000065 |

即使在严格延迟下，组内排序仍明显改善执行者 NLL（0.01544 [0.01379, 0.01705]）。但是这种改善没有明确传到固定个人头的动作预测：组内贡献主视图 0.000538 [0.000351, 0.000732]，严格延迟 0.000065 [-0.000028, 0.000154]。在这次单种子诊断中，传到动作预测的改善主要来自角色之间的概率重分配。这个分解只归因于模型权重变化，不是球员的因果效应；已固定的条件区域分布仍可能参与传导。四格 NLL、区间和十类结果见上面的 JSON。
